# Phase 2：讲解生成 Skill 执行计划

> 目标：将「题目 + 具体困惑点 + 可选尝试」转化为符合引擎契约的讲解包，并用 LC 80 与 LC 122 对 Skill 本身进行前向验证和迭代。

## 1. 固化 Skill 契约与教学约束

- 在仓库内创建可版本化的 `leetcode-explanation-generator` Skill。
- 要求调用前读取目标项目的 `docs/ENGINE-SPEC.md` 和 `engine/viz-registry.js`。
- 将八步教学结构写为不可跳过的检查清单，尤其约束第 1 步必须从零推导暴力解并呼应具体困惑点。
- 明确可视化决策流程：优先复用已注册组件；没有经过讨论不得新增引擎组件。

## 2. 用真实算法生成 LC 80 包

- 先为轨迹生成器写一个失败的结构校验，再实现真实读写双指针算法与 `--check`。
- 生成 `trace.json`、`meta.json`、`explain.md` 及题目页；Python/C++ 示例与生成器算法保持一致。
- 用具体删除搬移例子解释暴力解如何从直觉推出来，再解释排序带来的 `write - 2` 洞察。

## 3. 用真实算法生成 LC 122 包

- 先写失败的轨迹结构校验，再实现真实相邻日差贪心算法与 `--check`。
- 首先复用 `array-pointers`，仅绘制 `day` 指针，使用相邻两日高亮和 note 表示是否捕获涨幅与累计利润。
- 用具体连续上涨区间验证「一次买卖」与「逐日累加正差」的等价性；不添加新可视化组件。

## 4. 集成、浏览器验收与迭代报告

- 运行索引构建和全量测试；验证两份 JSON 与两种语言实现。
- 在本地浏览器逐帧检查两页的加载、控件、轨迹、Markdown、代码切换和控制台。
- 按四项评估维度审查真实输出，必要时收紧 Skill 文案或参考清单，并提交 Phase 2 完成报告。
