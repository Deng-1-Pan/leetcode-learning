## 原题

### 300. Longest Increasing Subsequence

Given an integer array `nums`, return the length of the longest strictly increasing subsequence.

### Example 1

Input: `nums = [10,9,2,5,3,7,101,18]`

Output: `4`

Explanation: The longest increasing subsequence is `[2,3,7,101]`, therefore the length is `4`.

### Example 2

Input: `nums = [0,1,0,3,2,3]`

Output: `4`

### Example 3

Input: `nums = [7,7,7,7,7,7,7]`

Output: `1`

### Constraints

- `1 <= nums.length <= 2500`
- `-10^4 <= nums[i] <= 10^4`

Follow up: Can you come up with an algorithm that runs in `O(n log(n))` time complexity?

## 题目拆解与通用切入点

**这题在考什么？** 主要考的是**算法思路**，不是某一种数据结构。数组只是题目给我们的数据容器；真正要练的是“怎样从一串数中找出最好的递增关系”。

第一层是动态规划：把大问题拆成很多小答案。第二层是贪心：同样长的答案只留下更有利于以后继续的一个。第三层是二分查找：更快地找到该替换的位置。所以后面有多种方案，不代表题目有互不相干的答案；它们是在同一个目标上，逐步减少重复工作。

**这次先学什么？** 先学“固定最后一个数”。暂时不管 DP、贪心这些名字。

看小数组 `[2,5,3]`。我们从左到右选数。`2 → 5` 可以，因为 `5` 比 `2` 大。走到 `3` 时，`3` 不能接在 `5` 后面，因为 `3 < 5`；但 `2 → 3` 可以，因为 `3 > 2`。

**5 秒想一想：** 这里数组最后的 `3`，下标是 `2`。若要求选出的序列必须以它结束，前面哪个数可以接在它前面？

**直接看答案：** 是下标 `0` 的 `2`。`2 < 3`，所以 `2 → 3` 仍严格递增。

这给我们第一个入口：不先找整条最长序列，而是逐个固定最后一个位置，问“如果必须以这里结束，最多能选几个数？”

**现在只需要记住：** LC 300 主要考“怎样表示和比较递增序列的历史”，第一步是固定最后一个位置。

:::insight
不要一开始找整条序列。先问每个位置“以我结尾时最好多长”。
:::

## 官方解法

### 方案一：动态规划

**这一小步要解决什么？** 我们已经会问“必须以某个位置结束时，最多选几个”。现在要把每个问题的答案存下来。

继续使用题目示例 `[10,9,2,5,3,7,101,18]`。先看下标 `2`：`nums[2] = 2`。如果序列必须以这个 `2` 结束，前面是 `10`、`9`；它们都比 `2` 大，不能接在 `2` 前面。只选 `2` 自己仍是一条长度为 `1` 的递增序列。

我们准备一张表：数组每个位置放一个答案。位置 `i` 的答案写作 `dp[i]`。所以 `dp[2] = 1` 的完整意思是：“以 `nums[2] = 2` 结束时，最长递增子序列有 1 项。”这就是“每格先是 1”的来源：每个数都可以独自成为一条序列。

现在轮到下标 `5`，也就是 `nums[5] = 7`。我们只检查它左边的数。下标 `2` 的 `2` 比 `7` 小，因此已知的序列 `[2]` 可以接上 `7`，变为 `[2,7]`。下标 `4` 的 `3` 也比 `7` 小；若表中 `dp[4] = 2`，它代表已有一条以 `3` 结束、长度为 2 的序列，例如 `[2,3]`。把 `7` 接上后，得到长度 `2 + 1 = 3` 的 `[2,3,7]`。

**5 秒想一想：** 现在已知 `dp[4] = 2` 且 `nums[4] = 3 < 7`。把 `7` 接在这条序列后，`dp[5]` 至少是多少？

**直接看答案：** 至少是 `3`。`dp[4]` 里的两项仍保留，再加当前位置的 `7` 这一项。

:::insight
`dp[i]` 不是整个数组的答案；它只回答“最后一个数固定为 `nums[i]`”时的答案。对每个 `i`，只从左边那些比它小的位置拿答案，加上当前数，再取最大的结果。
:::

:::viz approach="official-dp"
:::

时间 `O(n^2)`，空间 `O(n)`。

**现在只需要记住：** `dp[i]` 只看更小的前项，并取它们的最好长度加一。

### 方案二：构建候选序列（线性扫描）

**这一小步要解决什么？** DP 要比较很多前项。能不能同样长度只留一个最有用的结尾？

用 `sub` 记候选结尾。`[8,1,6,2]` 走到 `2` 时，`[1,6]` 的长度是 2。把 `6` 换成 `2` 后长度仍是 2，但以后更多数能接在 `2` 后。

**5 秒想一想：** 对以后来说，长度同为 2 时，结尾是 `2` 还是 `6` 更容易继续？

**直接看答案：** `2`。比 `2` 大的数更多，所以机会更多。

:::insight
同长度时留下更小的结尾；它不会减少当前长度，却会增加未来接续机会。
:::

:::viz approach="official-greedy-linear-scan"
:::

时间最坏 `O(n^2)`，空间 `O(n)`。

**现在只需要记住：** `sub` 记录的是“各长度最容易继续的结尾”。

:::pitfall
`sub` 不是最终 LIS。例如它可能变成 `[1,4,5]`，即使原数组里这三个数并不按该顺序出现。
:::

### 方案三：构建候选序列（二分查找）

**这一小步要解决什么？** 方案二每次从左找替换位置，仍然慢。

`sub` 从小到大排列。已经有 `[1,2,7]` 时，找 `3` 应放在哪里，就是找第一个不小于 `3` 的位置。因为数组有序，可以用二分查找，而不用一个格子一个格子找。

**5 秒想一想：** `3` 应替换 `[1,2,7]` 的哪一个数？

**直接看答案：** 替换 `7`。它是第一个 `>= 3` 的数。

:::insight
规则没变，只是把“从左找位置”换成了二分找位置。
:::

:::viz approach="official-greedy-binary-search"
:::

时间 `O(n log n)`，空间 `O(n)`。

**现在只需要记住：** 候选结尾有序时，用 `bisect_left` 找第一个 `>= 当前数` 的位置。

## 社区高赞解法

### 方案一：记忆化搜索

**这一小步要解决什么？** 用“先问更小问题”来写同一个 DP。

`dfs(i)` 的人话是：“先帮我算以第 i 个数结尾的长度。”它会问更早、更小的数。把已经算好的答案记下来（记忆化），下次再问同一格时直接拿结果。

**5 秒想一想：** 已经算过 `dfs(5)` 后，再次需要它时要重新递归吗？

**直接看答案：** 不用。缓存里已有答案。

:::insight
官方 DP 要先按下标从左到右填表，才知道算 `dp[5]` 时 `dp[2]`、`dp[4]` 已经在那里。换成递归时，计算 `dfs(4)` 会问一次 `dfs(2)`，随后计算 `dfs(5)` 又会问同一个 `dfs(2)`；两次的答案都是“以 `nums[2] = 2` 结尾，长度为 1”。第一次把 `dfs(2) = 1` 存下，第二次直接拿回这个值，就可以按需要提问而不必先设计填表顺序。
:::

:::viz approach="community-memoized-dfs"
:::

时间 `O(n^2)`，空间 `O(n)`。

**现在只需要记住：** 记忆化就是“算过一次，记下来，下次直接用”。

### 方案二：递推

**这一小步要解决什么？** 不用递归，也能填同一张答案表。

`f[i]` 和前面的 `dp[i]` 是同一个意思。区别只是顺序：递推从左到右填，轮到 `i` 时，左边答案已经写好。

**5 秒想一想：** 算 `f[5]` 时，可以直接使用 `f[0]` 到 `f[4]` 吗？

**直接看答案：** 可以。它们已经先被填好。

:::insight
记忆化算 `dfs(5)` 时，会临时检查 `dfs(2)`、`dfs(4)` 有没有缓存；递推则先算出 `f[2] = 1` 和 `f[4] = 2`，轮到 `i = 5` 时直接读取它们，得到同样的 `f[5] = 3`。两种写法保存的是同一张答案表，差别只在访问顺序：一个用到才算并查缓存，一个提前从左到右把左边全部填好。既然每个转移只依赖更左边的位置，顺序填表就不需要再判断“这格算过没有”。
:::

:::viz approach="community-iterative-dp"
:::

时间 `O(n^2)`，空间 `O(n)`。

**现在只需要记住：** 递推是按顺序填表；记忆化是需要时再问表。

### 方案三：贪心 + 二分（额外空间）

**这一小步要解决什么？** 把同长度、但结尾较大的候选删掉。

`g[k]` 的人话是：“长度为 k+1 时，最小的结尾。”若两个长度 2 的候选结尾是 `9` 和 `99999`，保留 `9` 就够了。`9` 更容易接上后面的数。

**5 秒想一想：** 长度相同，结尾 `9` 和 `99999`，该留谁？

**直接看答案：** 留 `9`。任何能接在 `99999` 后的数，也能接在 `9` 后。

:::insight
递推会给每个原下标留一格：`nums[0] = 10` 和 `nums[1] = 9` 都得到长度 1，但以后若一个数能接在 `10` 后，它一定也能接在更小的 `9` 后。长度相同的这两格里，`10` 就不必继续保留；每种长度只留下最小结尾即可。按长度留下的结尾会从小到大排列，于是把这些代表值放进 `g` 后，既压缩了重复状态，也能用二分找到该替换的位置。
:::

:::viz approach="community-greedy-binary-extra-space"
:::

时间 `O(n log n)`，空间 `O(n)`。

**现在只需要记住：** 相同长度只留最小结尾。

### 方案四：贪心 + 二分（原地修改）

**这一小步要解决什么？** `g` 需要空间；能不能借输入数组的前面格子？

`ng` 表示目前 `g` 有多长。把 `nums[0:ng]` 暂时当作笔记本。二分后把当前数写到对应格。写到末尾才让 `ng` 加一。

**5 秒想一想：** 替换中间的结尾时，`ng` 会增加吗？

**直接看答案：** 不会。长度没变，只是把同长度的结尾换小。

:::insight
额外空间版读到 `nums[5] = 7` 时，候选结尾只可能是像 `[2,3,7]` 这样的 3 格，而前面已经读过 6 个原数组位置。候选表的长度从不会超过已读元素数，所以这 3 格可以借用已经读完的 `nums[0:3]`，不会覆盖还没读取的 `nums[5]`。看出这个“候选前缀永远追不上读取位置”的关系后，就能把 `g` 原地放回输入数组，省掉新数组。
:::

:::viz approach="community-greedy-binary-in-place"
:::

时间 `O(n log n)`，额外空间 `O(1)`。

**现在只需要记住：** 前 `ng` 格只是候选结尾笔记，不是原输入的完整含义。

### 方案五：返回一个具体的 LIS

**这一小步要解决什么？** 前面的候选结尾能给长度，却不一定是一条真序列。若要交出一条序列，必须留下来路。

给每个数记一张“前一张卡片是谁”的纸条（前驱）。最长候选最后停在哪个原下标，就从那里沿纸条倒着走，最后反转。

**5 秒想一想：** 为什么回溯出来后要反转？

**直接看答案：** 因为我们从最后一个数往前找，顺序刚好反了。

:::insight
原地候选表先看到 `nums[0] = 10` 时会写下 `10`，再看到 `nums[1] = 9` 时就用 `9` 覆盖它；表还知道“长度 1 存在”，却已经忘了那条候选来自哪个原下标。若处理 `nums[5] = 7` 时决定接在 `nums[4] = 3` 后面，就额外记下 `previous[5] = 4`。候选表继续只负责长度，前驱表保留来路；最后从最长结尾沿前驱倒着走，再反转，就能还原一条具体 LIS。
:::

:::viz approach="community-reconstruct-lis"
:::

时间 `O(n log n)`，空间 `O(n)`。

**现在只需要记住：** 想返回具体序列，就额外记录每个数从哪里接过来。

## 复杂度对比

- 官方 DP、社区记忆化、社区递推：`O(n^2)` 时间，`O(n)` 空间。
- 官方线性候选序列：`O(n^2)` 时间，`O(n)` 空间。
- 三种候选结尾二分方案：`O(n log n)` 时间；额外数组版 `O(n)` 空间，原地版 `O(1)`。
- 返回具体 LIS：`O(n log n)` 时间，`O(n)` 空间。
