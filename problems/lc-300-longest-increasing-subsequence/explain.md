## 原题

### 300. Longest Increasing Subsequence

Given an integer array `nums`, return the length of the longest strictly increasing subsequence.

### Example 1:

Input: `nums = [10,9,2,5,3,7,101,18]`

Output: `4`

Explanation: The longest increasing subsequence is `[2,3,7,101]`, therefore the length is `4`.

### Example 2:

Input: `nums = [0,1,0,3,2,3]`

Output: `4`

### Example 3:

Input: `nums = [7,7,7,7,7,7,7]`

Output: `1`

### Constraints:

- `1 <= nums.length <= 2500`
- `-10^4 <= nums[i] <= 10^4`

## 暴力解法推导

你说自己“**一点思路都没有**”，那先不要要求自己马上找规律。最朴素的问题是：对每个数，我们到底要不要把它放进正在选择的序列里？比如看见 `10` 之后又看见 `9`，保留哪个，才不会错过后面的更长序列？

一个自然尝试是从第一个位置开始，不断做“选 / 不选”的决定，并确保新选的数比上一个选的数大。这样会枚举所有子序列；长度为 8 的示例就有 `2^8 = 256` 种选法，长度到 2500 时更不可能逐一试完。**这就是卡点的来源：不是不会写循环，而是每个位置都有两条分支，组合爆炸。**

若把每一条候选子序列都真的存下来，再找最长的一条，既慢又会反复比较相同的前缀。我们需要想办法：不保留所有历史选择，只保留“对以后最有用”的历史结果。

## 官方解法

### 从暴力的重复中抽出状态

先看示例中下标 `5` 的 `7`。它可以由 `[2,5,7]`（下标 `2,3,5`）得到，也可以由 `[2,3,7]`（下标 `2,4,5`）得到；两条都是长度 `3`、并且都在同一个 `7` 处结束。之后若要接上 `101`，只需要知道“有一条长度 `3` 的序列在这个 `7` 结束”，并不关心它途经了 `5` 还是 `3`。

这说明暴力法保存的完整路径有重复信息：对于同一结束下标，较短路径永远不如较长路径，而同样长的路径对未来完全等价。于是才可以固定最后一个数，问“**以 `nums[i]` 结尾时，最长能有多长？**”，并记作 `dp[i]`。

这正好压缩了暴力的重复：若 `nums[j] < nums[i]`，那么任何以 `nums[j]` 结尾的递增序列，都可以把 `nums[i]` 接在末尾。因此只需要在所有可接的 `j < i` 中取最好的一个：`dp[i] = max(dp[j] + 1)`。每个数自己也能独立成序列，所以初始值都是 `1`。

:::insight
`[2,5,7]` 和 `[2,3,7]` 虽然路径不同，却同为长度 `3` 且在同一个 `7` 结束；后面能否接上新数，对两者的判断完全相同。因此先由这对具体路径看出“同一结尾只需留下最长长度”，DP 才把完整路径压缩为每个结尾位置的一个数字。
:::

`dp` 最终为 `[1,1,1,2,2,3,4,4]`，最大值 `4` 就是答案。它不必记住具体哪一条序列，只需要保证每个结尾位置的“最好长度”正确。

## 社区高赞解法

官方 DP 在每个 `i` 都要扫描所有 `j < i`。看示例开头的 `10`、`9`、`2`：它们的 `dp` 都是 `1`，却不是同样有用。以后任何能接在 `9` 或 `10` 后面的数，也一定能接在更小的 `2` 后面；反过来，`5` 能接在 `2` 后面，却不能接在 `9` 或 `10` 后面。

所以在“长度同为 1”的候选里，`9` 和 `10` 都被 `2` 严格支配，可以丢弃。把这个观察推广到每一种长度：与其保留所有 DP 结尾，只保留该长度的最小结尾就够了；这份按长度保存的最小结尾数组才叫 `tails`。

处理一个 `num` 时，若它比 `tails` 的所有值都大，就能把最长长度加一；否则替换掉第一个 `>= num` 的结尾。这个替换不增加长度，却让同一长度的候选更有发展空间。因为 `tails` 始终递增，“第一个 `>= num`”可以二分找到。

:::insight
在长度 `1` 的候选 `10`、`9`、`2` 中，未来的 `5` 只能接在 `2` 后面，而能接在 `9` 或 `10` 后面的数也必能接在 `2` 后面。先由这个支配关系看出每种长度只需保留最小结尾，才得到 `tails`；替换第一个 `>= num` 只是把同长度候选的结尾继续压低，给未来更多机会。
:::

播放器中的数组就是实时的 `tails`；`slot` 指向二分找到的插入或替换位置。每一帧都显示处理后的真实算法状态。

:::viz approach="community-greedy-binary-search"
:::

:::pitfall
`tails` 不一定是原数组中的一个真实子序列。例如输入 `[3,4,5,1]` 时它会变成 `[1,4,5]`，但长度 `3` 仍然正确。我们只借它保存“每种长度最小的结尾”，而不是复原答案序列。
:::

这个方案相对官方 DP 的选定路线，把每个位置要比较的前驱从线性扫描缩成二分查找，因而值得单独展示一套可视化。

## 复杂度对比总结

- **选 / 不选的暴力枚举**：时间 `O(2^n)`；至少 `O(n)` 递归路径空间；保留每一种候选子序列。
- **官方动态规划**：时间 `O(n^2)`；空间 `O(n)`；保留每个结尾位置的最佳长度。
- **社区贪心 + 二分**：时间 `O(n log n)`；空间 `O(n)`；保留每个长度的最小可能结尾。
