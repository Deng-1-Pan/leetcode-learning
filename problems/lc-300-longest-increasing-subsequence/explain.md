## 原题

### 300. Longest Increasing Subsequence

Given an integer array `nums`, return the length of the longest strictly increasing subsequence.

### Example 1

Input: `nums = [10,9,2,5,3,7,101,18]`

Output: `4`

Explanation: The longest increasing subsequence is `[2,3,7,101]`, therefore the length is `4`.

### Example 2

Input: `nums = [0,1,0,3,2,3]`

Output: `4`

### Example 3

Input: `nums = [7,7,7,7,7,7,7]`

Output: `1`

### Constraints

- `1 <= nums.length <= 2500`
- `-10^4 <= nums[i] <= 10^4`

Follow up: Can you come up with an algorithm that runs in `O(n log(n))` time complexity?

## 题目拆解与通用切入点

**先翻译题目。** 子序列就是“可以跳过，但不能调换顺序”。严格递增就是后一个数必须更大。题目只要长度，不要求真的交出那条序列。

看 `[2,5,3]`。`[2,5]` 是递增的。`3` 不能接在 `5` 后面，但可以和 `2` 组成 `[2,3]`。所以困难是：看到一个新数时，前面许多不同选择里，哪一个值得记住？

**5 秒想一想：** 在 `[2,5,3]` 中，`3` 可以接在 `5` 后面吗？

**直接看答案：** 不可以，因为 `3` 比 `5` 小；它可以接在 `2` 后面。

第一种通用入口是固定最后一个数：问“以当前位置结尾，最长能多长？”这叫把大问题拆成小答案。之后再问：同长度的两个小答案，是否只留一个更容易继续的代表？

**现在只需要记住：** 先固定最后一个数，序列题就有了可以开始填写的小问题。

:::insight
不要一开始找整条序列。先问每个位置“以我结尾时最好多长”。
:::

## 官方解法

### 方案一：动态规划

**这一小步要解决什么？** 给每个位置一个小答案。

`dp[i]` 的人话是：“以 `nums[i]` 结束时，最长有几项。”单独一个数也算序列，所以每格先是 `1`。要算 `7` 时，只看它前面更小的数；例如 `2` 和 `3` 都能接在 `7` 前面，把它们的最好长度加一，选较大者。

**5 秒想一想：** 若以 `3` 结尾的最好长度是 `2`，把 `7` 接在后面后长度是多少？

**直接看答案：** 是 `3`。原来的两项还在，再加上 `7`。

:::insight
`dp[i]` 不是整个数组的答案；它只回答“最后一个数固定为 i”时的答案。
:::

:::viz approach="official-dp"
:::

时间 `O(n^2)`，空间 `O(n)`。

**现在只需要记住：** `dp[i]` 只看更小的前项，并取它们的最好长度加一。

### 方案二：构建候选序列（线性扫描）

**这一小步要解决什么？** DP 要比较很多前项。能不能同样长度只留一个最有用的结尾？

用 `sub` 记候选结尾。`[8,1,6,2]` 走到 `2` 时，`[1,6]` 的长度是 2。把 `6` 换成 `2` 后长度仍是 2，但以后更多数能接在 `2` 后。

**5 秒想一想：** 对以后来说，长度同为 2 时，结尾是 `2` 还是 `6` 更容易继续？

**直接看答案：** `2`。比 `2` 大的数更多，所以机会更多。

:::insight
同长度时留下更小的结尾；它不会减少当前长度，却会增加未来接续机会。
:::

:::viz approach="official-greedy-linear-scan"
:::

时间最坏 `O(n^2)`，空间 `O(n)`。

**现在只需要记住：** `sub` 记录的是“各长度最容易继续的结尾”。

:::pitfall
`sub` 不是最终 LIS。例如它可能变成 `[1,4,5]`，即使原数组里这三个数并不按该顺序出现。
:::

### 方案三：构建候选序列（二分查找）

**这一小步要解决什么？** 方案二每次从左找替换位置，仍然慢。

`sub` 从小到大排列。已经有 `[1,2,7]` 时，找 `3` 应放在哪里，就是找第一个不小于 `3` 的位置。因为数组有序，可以用二分查找，而不用一个格子一个格子找。

**5 秒想一想：** `3` 应替换 `[1,2,7]` 的哪一个数？

**直接看答案：** 替换 `7`。它是第一个 `>= 3` 的数。

:::insight
规则没变，只是把“从左找位置”换成了二分找位置。
:::

:::viz approach="official-greedy-binary-search"
:::

时间 `O(n log n)`，空间 `O(n)`。

**现在只需要记住：** 候选结尾有序时，用 `bisect_left` 找第一个 `>= 当前数` 的位置。

## 社区高赞解法

### 方案一：记忆化搜索

**这一小步要解决什么？** 用“先问更小问题”来写同一个 DP。

`dfs(i)` 的人话是：“先帮我算以第 i 个数结尾的长度。”它会问更早、更小的数。把已经算好的答案记下来（记忆化），下次再问同一格时直接拿结果。

**5 秒想一想：** 已经算过 `dfs(5)` 后，再次需要它时要重新递归吗？

**直接看答案：** 不用。缓存里已有答案。

:::viz approach="community-memoized-dfs"
:::

时间 `O(n^2)`，空间 `O(n)`。

**现在只需要记住：** 记忆化就是“算过一次，记下来，下次直接用”。

### 方案二：递推

**这一小步要解决什么？** 不用递归，也能填同一张答案表。

`f[i]` 和前面的 `dp[i]` 是同一个意思。区别只是顺序：递推从左到右填，轮到 `i` 时，左边答案已经写好。

**5 秒想一想：** 算 `f[5]` 时，可以直接使用 `f[0]` 到 `f[4]` 吗？

**直接看答案：** 可以。它们已经先被填好。

:::viz approach="community-iterative-dp"
:::

时间 `O(n^2)`，空间 `O(n)`。

**现在只需要记住：** 递推是按顺序填表；记忆化是需要时再问表。

### 方案三：贪心 + 二分（额外空间）

**这一小步要解决什么？** 把同长度、但结尾较大的候选删掉。

`g[k]` 的人话是：“长度为 k+1 时，最小的结尾。”若两个长度 2 的候选结尾是 `9` 和 `99999`，保留 `9` 就够了。`9` 更容易接上后面的数。

**5 秒想一想：** 长度相同，结尾 `9` 和 `99999`，该留谁？

**直接看答案：** 留 `9`。任何能接在 `99999` 后的数，也能接在 `9` 后。

:::viz approach="community-greedy-binary-extra-space"
:::

时间 `O(n log n)`，空间 `O(n)`。

**现在只需要记住：** 相同长度只留最小结尾。

### 方案四：贪心 + 二分（原地修改）

**这一小步要解决什么？** `g` 需要空间；能不能借输入数组的前面格子？

`ng` 表示目前 `g` 有多长。把 `nums[0:ng]` 暂时当作笔记本。二分后把当前数写到对应格。写到末尾才让 `ng` 加一。

**5 秒想一想：** 替换中间的结尾时，`ng` 会增加吗？

**直接看答案：** 不会。长度没变，只是把同长度的结尾换小。

:::viz approach="community-greedy-binary-in-place"
:::

时间 `O(n log n)`，额外空间 `O(1)`。

**现在只需要记住：** 前 `ng` 格只是候选结尾笔记，不是原输入的完整含义。

### 方案五：返回一个具体的 LIS

**这一小步要解决什么？** 前面的候选结尾能给长度，却不一定是一条真序列。若要交出一条序列，必须留下来路。

给每个数记一张“前一张卡片是谁”的纸条（前驱）。最长候选最后停在哪个原下标，就从那里沿纸条倒着走，最后反转。

**5 秒想一想：** 为什么回溯出来后要反转？

**直接看答案：** 因为我们从最后一个数往前找，顺序刚好反了。

:::viz approach="community-reconstruct-lis"
:::

时间 `O(n log n)`，空间 `O(n)`。

**现在只需要记住：** 想返回具体序列，就额外记录每个数从哪里接过来。

## 复杂度对比

- 官方 DP、社区记忆化、社区递推：`O(n^2)` 时间，`O(n)` 空间。
- 官方线性候选序列：`O(n^2)` 时间，`O(n)` 空间。
- 三种候选结尾二分方案：`O(n log n)` 时间；额外数组版 `O(n)` 空间，原地版 `O(1)`。
- 返回具体 LIS：`O(n log n)` 时间，`O(n)` 空间。
